## 结论

已完成“粗切 → 第一 Agent 识别装配特征 → 生成明确选区 JSON → 0.01 mm 整平面细切/重渲染 → 第二 Agent 联合判断”的串行动态切片原型。

首轮只测试 `easy_1`、`medium_1`、`hard_9` 各一件。流程三件全部成功，但效果并非全面改善，因此未扩大到 29 件：动态流程显著减少误检，`medium_1` 的坐标和尺寸判断却明显退化。

## 实际选区与开销

| 样本 | 第一 Agent 装配特征数 | 实际细切区间 | 细切层数 | 细切耗时 | Agent 耗时 | Tokens |

| `easy_1` | 1 | Z: 0–10 | 1,001 | 18.1 s | 42.1 s | 36,232 |
| `medium_1` | 3 | X: 21.5–23.5; Y: 9–11、34–36; Z: 0–38.87 | 4,490 | 96.3 s | 80.9 s | 53,262 |

运行后审计发现，粗切受每轴 30 层上限影响，末层可能离真实端面一个粗切间距。最终实现已将匹配区间余量自动提升到“不小于该轴粗切间距”，因此当前代码会把 `medium_1` 的 Z 区间补齐到 0–40、`hard_9` 补齐到 Y: 0–25 和 Z: 18–45；对应计划层数为 4,604 和 5,202。该边界修复已通过计划单元测试，未再次消耗模型调用重跑指标。

## 实现要点

- 第一 Agent 输出中的 `作用=装配特征` 决定优先细切对象。
- 孔/柱按类型和归一化三维中心距离匹配粗切 JSON，并采用该特征完整轴向深度范围。
- 视觉特征没有可靠粗 JSON 匹配时，在 X/Y/Z 三轴各建立窄范围，避免静默退化为全模型细切。
- 重叠区间按轴合并，计划写入 `*_fine_slice_plan.json`；超过可配置总层数上限时明确失败。
- 细切几何恢复全局坐标和完整包络尺寸；第二 Agent 同时接收细切图、细切 JSON、选区计划和第一 Agent 结论。
- 动态几何临时文件有进程内锁，允许模型并发时串行保护旧流水线的固定中间文件名。
